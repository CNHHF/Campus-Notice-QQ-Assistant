# 校园通知 QQ 服务

作者：HHF。独立实现，仅借鉴 qq-bridge 的 OneBot 桥接思路，未复制其代码。第三方程序独立安装，不随本仓库分发。

本机启动：双击 `start-qq.bat`。管理页 `http://127.0.0.1:8788`，启动入口自动登录。
桌面原「校园通知推送」入口仍指向根目录 `start-all.bat`，现在统一启动网关、抓取工作台、微信桥和管理服务，然后弹出本管理页。抓取工作台使用 `--no-open --serve-only`，不另弹页面、不重复开启启动抓取。左侧「校园通知工作台」内嵌原 `8765` 页面，原功能保留。
`start-qq.bat`也走同一套完整启动流程；缺失服务会由`start-services.ps1`拉起，已有进程跳过。网关需端口就绪后才启动微信桥，QQ客户端初次/失效登录仍由本人完成。管理页明确显示微信网关与桥的运行状态。仅打开网页地址不会启动这些后台服务。
Python 3.12 标准库，无需安装 Python 依赖。保留现有微信桥，QQ 服务不发起抓取，仅每 60 秒检查共享的只读通知库；学校抓取仍由微信桥按 60 分钟执行。

## 当前功能

- 管理私聊 QQ 白名单和群白名单，启停群自动推送。
- 群查询每条消息必须含 OneBot `at` 段且目标为 bot 的实际 QQ 号；名字、引用、普通聊天、拍一拍和 @全体均不触发。
- 群推送可以主动发送，与“查询仅 @ 回复”分别控制。
- 群成员可 @ 查询，只有私聊白名单里的账号可私聊。上下文按 `群号+QQ号` 或 `private+QQ号` 隔离，20 分钟过期，仅含获准查询。`/reset` 清空自己的当前会话。
- `查通知 奖学金`、`最新通知`、`第2条详情`无需模型；自然语言查询通过 DeepSeek 转为受约束的搜索参数。结果由数据库生成，每条附原文链接，不编造内容。
- 新群基线记录全部已有标题，避免历史洪水；推送沿用微信过滤规则，额外拦住无效、缺失、未来的发布日期；跨栏目同标题只发一次。
- 发送前持久化状态；超时、异常回执、进程中断导致结果不确定时保留 `uncertain`，不自动重发。明确失败留待下次重试。
- 普通群聊、私人查询正文、API Key 不记录在活动日志中。

第一版不做附件下载、身份绑定、Cookie 保存、任意闲聊、远程执行、语音和表情包。绝不读取或共享现有教务 cookie。

## 微信扫码授权

管理页「接入设置」增加微信扫码入口，按需启动本机 `openclaw channels login --channel openclaw-weixin`，不自动重新授权已有账号。二维码用已安装官方插件依赖在本地渲染，不向外部二维码服务传输。支持手机确认、配对数字和取消；取消只结束页面创建的登录子进程，不停止网关。

授权信息由官方插件保存。页面不会修改现有微信桥的 target；换账号后必须另外核对推送目标。扫码授权与微信推送会话刷新是两件事，完成后仍需给 bot 发一条消息。此功能依赖本机已安装的 Node.js、OpenClaw 和腾讯微信插件，云迁移时需重新安装相关组件。

## QQ 客户端接入

本服务使用 OneBot v11 HTTP 协议，不依赖 DeepSeek Harness 或 SnowLuma。可使用 NapCat 等兼容客户端。

官方安装说明：https://napneko.github.io/guide/boot/Shell
官方网络配置：https://napneko.github.io/config/basic

1. 安装 QQ 客户端并登录备用机器人账号，由本人扫码。
2. 管理页「接入设置」填写机器人 QQ，保存。
3. 在 OneBot 客户端添加 HTTP 服务端：`127.0.0.1:3000`，消息格式 `array`。
4. 添加 HTTP 客户端（事件上报）：`http://127.0.0.1:8788/onebot/events`，消息格式 `array`，不报告自身消息。
5. 下载管理页提供的 OneBot 配置示例，两边使用相同 Token。注意示例含机密，只在本机使用。
6. 「检查 QQ 连接」确认登录的 QQ 与设置一致；将 bot 加入测试群，添加群号，再打开自动推送。
7. 私聊用户需先成为机器人好友并获得页面授权；页面授权不会自动添加好友或拉群。

事件验证接受同 Token 的 Bearer 鉴权，或 OneBot 的 `X-Signature: sha1=...`。端口仅监听本机，不对公网开放。

## DeepSeek

通过管理页保存 Key 或设置 `DEEPSEEK_API_KEY`。也可读取现有 OpenClaw DeepSeek provider 的直接 Key/环境引用；不复制其它凭据。默认 `deepseek-flash`，按账号实际可用模型选择。
Key 保存在被忽略的 `runtime/config.json`，普通管理接口不返回；本机管理员可访问该文件。推送、页面搜索和命令式搜索不调用模型。自然语言查询仅一次参数解析调用，默认输出上限 250 token；活动页显示实际 token 用量，不保证固定费用。

兼容新版 OpenClaw 学校 bot 的 SQLite 凭据：仅只读提取 DeepSeek API Key，不复制到本项目配置。默认 agent 为 `school-bot`，可通过 `OPENCLAW_AGENT_ID` 指定。简短参数解析禁用模型思考模式，避免思考耗尽250 token 后返回空内容，已用真实模型请求验证。

## 数据与维护

`runtime/config.json`：管理口令、OneBot Token、API Key、访问名单；`runtime/service.db`：推送状态、脱敏活动和用量。必须备份，不能入库。不要删除状态后重发历史，不确定送达的记录需先问用户。

启动幂等；停止：结束命令行包含绝对路径 `qq-service/app.py` 的 Python 进程。启动不改开机自启设置。

运行测试：`python -m unittest discover -s qq-service/tests -v`。测试使用临时 SQLite 和模拟 OneBot，不连接真实 QQ、不改真实推送状态。

后续云迁移需搬迁服务状态并配置访问认证、HTTPS、OneBot 私网连接及学校抓取器。不能把本机管理页直接暴露公网。微信和 QQ 去重状态各自独立；保留同一轮学校抓取，勿另增抓取调度。

## 开源部署路径

支持仓库 `bridge/` 或已有部署 `weixin-bridge/`。默认部署根目录为仓库根；`CAMPUS_DEPLOY_ROOT` 可指定已有部署目录，`RADAR_DB` 可指定数据库。保留根 `start-all.bat` 与 `qq-service/` 的相对关系。启动前先填写微信桥配置，勿直接对真实状态跑 dry-run，超时不重发。
